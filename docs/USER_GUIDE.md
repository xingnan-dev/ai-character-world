# 日常使用／演示顺序

先按[本地运行说明](LOCAL_RUN.md)启动两个终端。使用自己的账号和非敏感内容；演示可以单独建账号。以下描述现有功能，不包括未来规划。

1. **注册并登录。** 新建一个 USER Character，设置名称和身份，在角色列表点“设为当前身份”。
2. **创建 AI Character。** 填姓名、身份、核心性格和说话风格。保存后进入详情，编辑并刷新确认读回。图片配置是可选的，不必等待图片生成才能聊天。
3. **开始聊天。** 从 AI 详情点“开始对话”。若输入框尚未出现，在左侧列表选择刚创建的会话；当前角色和身份以会话冻结快照为准。发送简短问题，观察等待／回复状态，完成后刷新并从列表重新选择原会话，确认消息内容和终态。
4. **观察连续性。** 明确告诉角色一条虚构偏好，待回复与后处理结束后开新会话，用不同问法查询。相同会话答对不证明长期记忆；角色记忆保留原文值，不保证自由概括或任意语义检索。关系和成长只在评估认为有稳定／有意义证据时变化，不是每轮升级。
5. **可选 World。** 创建背景／规则／场景，设置 USER 身份，添加 2–4 个 AI。输入一条行动后发起 Round，等待角色按序发言，刷新查看 timeline。有 Round 后阵容冻结，世界语义仍可编辑；已有 Round/参与者快照不会跟随源资料漂移。Round 完成不等于 World Memory 后处理完成。
6. **可选只读 Agent。** 打开 Agent Workspace，目标包含自己资源的 ID 和所需资料，例如“读取我的角色上下文和世界场景，缺少信息就说明未知”。当前工具只有角色上下文、角色记忆搜索、世界上下文，不能创建或修改业务资源。查看参数、Observation、FINAL，使用 Recent Runs 和 `runId` 返回原任务；手动选旧 Step 后不会被更新抢走。

## 中断时怎么做

- 聊天“停止生成”与页面刷新可能需要等待服务端确认；当前不保存未完成的部分回复，不保证 Provider 已停止计算或计费。确认终态后再继续。
- World 页面断开不等于取消后台。服务重启后未过期的执行先观察；过期后点击“恢复执行”或重新进入页面，已有 Event 保留。终态部分失败不自动重做失败角色。
- Agent 只在后端授权的 PENDING / stale RUNNING 状态提供 Start／Resume；FAILED 和 COMPLETED 不意味着可以重新执行。查看失败 Step，不反复点击制造新任务。
- 不清空数据库、删除生成图片或改旧迁移来处理一次请求失败。已知边界见[限制与待办](KNOWN_LIMITATIONS.md)。

## 建议的最终整体验收顺序

用一个全新独立库与专用账号，按“登录 → USER/AI 创建编辑 → 一次真实聊天 → 刷新读回 → World 最小两角色互动 → 只读 Agent 查询 → 正常停止／同库重启”检查交付路径。控制真实调用量，记录所用版本；不能把 Mock／受控结果写成真实 AI 通过。
